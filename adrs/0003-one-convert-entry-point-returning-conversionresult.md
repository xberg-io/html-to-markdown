# One convert entry point returning ConversionResult

## Context and Problem Statement

Through the 2.x line the core grew one public function per output: `convert` returned a `String`, and
`convert_with_metadata`, `convert_with_inline_images`, `convert_with_tables`, `convert_with_visitor`
and `convert_with_async_visitor` returned the extra data. Every language binding had to expose each of
them.

## Considered Options

* One `convert()` that returns a `ConversionResult` with content, document, metadata, tables, images
  and warnings
* The `convert_with_*` family alongside a `String`-returning `convert` (the 2.x API)

## Decision Outcome

Chosen option: "One `convert()` that returns a `ConversionResult` with content, document, metadata,
tables, images and warnings", because one entry point gives every binding the same surface, and the
options decide which parts of the result are filled.

* 690665d4de (2026-03-27) made `convert()` return a `ConversionResult`, keeping an `extract()` alias and a
  `String`-returning `convert_to_string()` shim, and c5b8bb9799 (2026-03-28) removed both, leaving the single
  `convert()`. 941bc1b5f1 (2026-03-28) cut the bindings down to it.
* a7dde300d1 and 21dbc3aff8 (2026-03-29) removed the remaining `convert_with_*` functions and the async
  visitor from the public API. The change shipped as 3.0.0 on 2026-03-30.
* 13b936e08a (2026-05-02) narrowed the surface to `convert(html, options)` by moving the visitor into
  `ConversionOptions` (ADR 0004) and dropping the public JSON option helpers.
* `convert_with_accessible_names` is the same conversion with an explicit accessible-name policy, and
  returns the same `ConversionResult`.
* The bindings that expose this API are generated by alef, per
  [org ADR-0002 (Rust cores with alef-generated bindings)](https://github.com/xberg-io/agent-conventions/blob/main/adrs/0002-rust-cores-with-alef-generated-bindings.md).

### Consequences

* Good, because each binding exposes one function and one result type.
* Good, because one walk produces content, tables, metadata and images together.
* Bad, because 3.0.0 broke every caller of the 2.x functions and every caller that expected a `String`.
